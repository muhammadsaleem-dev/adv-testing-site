7. Risk & Model-Based

Key concepts and techniques

🎯 Chapter 7 Core Mission: Risk-Based Testing (RBT) & Test Level Selection

You can never test everything. Risk-Based Testing (RBT) ensures that testing resources are ruthlessly focused where failure costs the most. Calculate Risk Exposure (Probability × Impact) and assign rigorous test responses.

1. Risk Identification & Exposure Calculation

A Risk is a potential problem that may happen in the future, defined by two fundamental dimensions:

📐 The Risk Exposure Formula:

Risk Exposure = Probability (Likelihood) × Impact (Damage)
Risk Description Probability (1–3) Impact (1–3) Exposure (P×I) Assigned Test Response
Transfer above limit approved 2 3 6 Boundary value + negative API/System tests
Expired session permits transfer 2 3 6 Integration tests with expired token injection
Invalid currency accepted 2 2 4 Equivalence class validation tests
Login page typo / CSS glitch 2 1 2 Low-priority visual review

2. Deep vs. Light Testing Justification Matrix

In the exam, the professor asks you to contrast a feature that must be tested deeply against one tested lightly using 5 criteria:

Criteria Test Deeply (e.g. Transfer Validation) Test Lightly (e.g. Dashboard Theme)
Probability High (Complex business & boundary logic). Low (Static CSS values rarely break logically).
Impact Critical (Direct financial loss / regulatory fine). Low (Minor visual annoyance).
Req. Criticality Core business compliance requirement. Non-essential aesthetic preference.
Test Cost High ROI — cost of defect astronomically exceeds test cost. Low ROI — visual regression maintenance is costly.
Required Confidence Stakeholders demand 100% proof before deployment. Stakeholders accept hotfixing visual bugs post-release.
