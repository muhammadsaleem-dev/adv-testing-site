🏛️ Official Q AI DEFECT PATTERNS (4 P)

Source: CH05_AdvTest_06_AICover_Static.pdf

A Copilot-generated function for FinCon account tier classification:

def get_tier(balance: float, months_active: int) -> str: if balance >= 50000 and months_active >= 12: return 'platinum' elif balance >= 10000 and months_active >= 6: return 'gold' elif balance >= 1000 and months_active >= 1: return 'silver' elif balance >= 1000 and months_active >= 1: # line X return 'bronze' else: return 'basic'
  • The specification defines only: platinum, gold, silver, basic. No bronze tier exists.

Perform the following tasks:

  • (a) Identify all defects in this function.
  • (b) Explain why 100% branch coverage would NOT reveal these defects without an independent test oracle.
  • (c) Write two test cases that, together, reveal both defects.

Suggested Answer:

(a) Defects identified (1.5 P):

  • Defect 1 (Dead Code): Line X is structurally unreachable. The conditions for silver and bronze are identical, meaning any input that satisfies Line X will be intercepted by the silver branch first.
  • Defect 2 (Hallucination): The AI hallucinated a 'bronze' return value that does not exist in the official specification.

(b) Why branch coverage fails without an oracle (1.5 P):

A tester deriving tests purely from the code (white-box) to achieve branch coverage will notice that Line X cannot be reached. However, without consulting the specification (an independent test oracle), they will not know why it is dead. They might assume the condition for bronze was coded incorrectly, rather than realizing that bronze is a complete hallucination that shouldn't exist at all.

(c) Test cases to reveal defects (1 P):

  • TC 1 (Coverage tool check): Input balance=1000, months_active=1. Expected: silver. Actual: silver. A coverage tool will flag Line X as unexecuted (revealing dead code).
  • TC 2 (Traceability check): Attempt to map the code branch for 'bronze' back to a test case derived from the requirements. Expected: No test case exists for bronze (revealing hallucination).
🏛️ Official Q STATIC ANALYSIS (3 P)

Source: CH05_AdvTest_06_AICover_Static.pdf

A colleague writes the following function:

def batch_transfer(transfers: list, db, logger=[]) -> int: success_count = 0 for tx in transfers: result = db.execute(tx) if result.ok: success_count += 1 logger.append(tx.id) if success_count > 0: summary = f"Completed {success_count} transfers" return success_count

Perform the following tasks:

  • (a) Identify two static defects in this function using the defect category table.
  • (b) For each defect, state which tool (pylint/mypy/ruff) would most likely detect it and why.

Suggested Answer:

(Following the strict examiner rubric: Defect → Reason → Likely Tool)

(a & b) Static Defects and Tools (3 P):

  • Defect 1: Mutable default argument (logger=[]).
    Reason: The list is instantiated only once when the function is defined. Subsequent function calls will share the exact same list instance, causing unintended cross-call state leakage.
    Likely Tool: Pylint (or Ruff). It has dedicated rules (e.g., W0102 dangerous-default-value) designed to flag mutable default arguments in Python.
  • Defect 2: Unused local variable (summary).
    Reason: The variable summary is assigned a formatted string but is never returned, logged, or utilized anywhere in the function.
    Likely Tool: Ruff (or Pylint). Linters aggressively flag variables that are assigned but never accessed (e.g., F841) as they indicate logic errors or dead code.
🏛️ Official Q INSPECTION VS. COVERAGE (3 P)

Source: CH05_AdvTest_06_AICover_Static.pdf

A colleague argues:

"If we achieve 80% branch coverage, we don't need code inspection — coverage is more rigorous because it's automated and objective."

Perform the following tasks:

  • (a) Give two concrete examples from today's material where 100% branch coverage would miss defects that inspection finds.
  • (b) Give one example where automated static analysis catches a defect that neither branch coverage nor inspection reliably catches.

Suggested Answer:

(a) Where branch coverage fails but inspection succeeds (2 P):

  • Missing requirements (Omissions): If a critical feature (e.g., verifying a user's age) is completely omitted from the code, 100% branch coverage of the existing code will easily be achieved. Coverage cannot detect what isn't there, but a human inspecting against the specification will immediately spot the missing logic.
  • Incorrect Constants / Hallucinations: If a developer codes a constant wrong (e.g., TAX_RATE = 0.50 instead of 0.05), tests written to cover the code will blindly assert the wrong value. Inspection catches semantic errors that structural coverage ignores.

(b) Where static analysis outperforms both (1 P):

Memory leaks, race conditions, or mutable default arguments (e.g., logger=[]). A human inspector might easily gloss over a `[]` bracket in a function definition due to visual fatigue. A unit test suite might only call the function once, meaning the shared-state bug never triggers. Static analysis algorithms, however, instantaneously flag this exact syntax anti-pattern without needing execution or human attention.
