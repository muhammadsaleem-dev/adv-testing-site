3. Pairwise & Decision Tables

Key concepts and techniques

EC and BVA focus on individual parameters. Pairwise and decision tables focus on interactions.

Pairwise testing

  • Guarantee: every combination of values between every pair of parameters appears at least once.
  • It does not guarantee every 3-way or full combination.
  • The largest 2-way pair gives a lower bound for the number of rows.
  • Always verify the table; do not claim pairwise coverage only because the row count looks reasonable.

Cause-effect graphing

  1. Divide the specification into a manageable rule.
  2. List causes: input conditions or equivalence classes.
  3. List effects: outputs, messages or state changes.
  4. Connect them using Boolean logic (identity, NOT, AND, OR).
  5. Add constraints for impossible combinations (Exclusive, Inclusive, One and only one).
  6. Convert the graph into a decision table.
  7. Create one test case per decision-table column.

Worked exam questions

✏️ Pairwise guarantee (4 marks) (Source) (Source) Explain what pairwise guarantees and does not guarantee.

It guarantees that every 2-way value combination appears in at least one test. It does not guarantee all 3-way or full combinations, so defects requiring three simultaneous conditions can remain.

✏️ Overdraft decision table (4 marks) Protection enabled, balance sufficiency and overdraft limit determine approval.

State assumptions because the wording is ambiguous. A reasonable table is: sufficient balance -> approve; insufficient + protection + limit not exceeded -> approve; insufficient + no protection -> INSUFFICIENT_FUNDS; insufficient + protection + limit exceeded -> OVERDRAFT_LIMIT_EXCEEDED. “Limit exceeded” without protection can be marked impossible/not applicable.

✏️ Review AI debit tests (4 marks) AI says inactive+sufficient -> INSUFFICIENT_FUNDS and active+0 balance+1 amount -> approved.

Both are wrong. Inactive takes priority and should return ACCOUNT_INACTIVE. An active account with insufficient balance should return INSUFFICIENT_FUNDS. The missing combination is inactive plus insufficient balance; expected ACCOUNT_INACTIVE.
