3. Pairwise & Decision Tables

Key concepts and techniques

🎯 Chapter 3: Pairwise Testing & Cause-Effect Graphing

Why test billions of combinations when most bugs are caused by the interaction of just 2 parameters? Learn how to slash test suites by 80–95% using Pairwise Testing, and master Cause-Effect Graphing to turn complex business rules into simple Decision Tables.

1. When EC + BVA is Not Enough (The Autopilot Problem)

Equivalence Partitioning and Boundary Value Analysis test each parameter in isolation. However, real software bugs hide in the interaction between parameters:

✈️ The Famous Airplane Analogy (Slide 6):

"Would you expect the autopilot to switch off if the toilet is flushed?"

Individually, the toilet flush works perfectly, and the autopilot works perfectly. But when combined simultaneously, an unexpected bug triggers! EC & BVA test them separately and miss this completely.

The Combinatorial Explosion Problem

  • For a FinCon transfer form with 4 parameters (3 values each): 3 × 3 × 3 × 3 = 81 test cases.
  • For a configuration screen with 10 parameters (3 values each): 310 = 59,049 test cases (Impossible to test manually!).

2. Pairwise Testing: The 2-Way Magic

🔑 The Key Insight (Slide 8):

Empirical studies show that over 80% of software defects are triggered by the interaction of just two parameters (2-way interaction), not three or more.
Instead of testing every full combination, we test every pair of parameter values at least once. This slashes test cases by 80–95% while keeping high defect-finding power!

📐 The Pairwise Minimum Rule (Exam Essential):

The absolute minimum number of test cases required for pairwise coverage equals the product of the number of values of the two largest parameters:

Pairwise Minimum ≥ (Values in Largest Param 1) × (Values in Largest Param 2)

The Lecture Slide Print Dialog Example (Slides 9–10)

Given 4 print settings:

  • Print Header: Checked / Unchecked (2 values)
  • Print Logo: Yes / No (2 values)
  • Print Footer: Checked / Unchecked (2 values)
  • Print Date: Today / Last saved / Special date (3 values)

• Full Combinations: 2 × 2 × 2 × 3 = 24 test cases.
• Pairwise Minimum: Largest pair is Header (2) × Date (3) = 6 test cases!

Test Case # Header Logo Footer Date
TC 1 Checked Yes Checked Today
TC 2 Checked No Unchecked Last saved
TC 3 Checked Yes Unchecked Special date
TC 4 Unchecked No Checked Today
TC 5 Unchecked Yes Unchecked Last saved
TC 6 Unchecked No Checked Special date

Every 2-way pair between any two columns appears at least once in just 6 test cases instead of 24!

🏦 FinCon Transfer Form Exercise (Slide 13):

  • amount: small (500), boundary (100k), oversized (200k) → 3 values
  • currency: EUR, USD, invalid → 3 values
  • target_account_exists: yes, no → 2 values
  • session_valid: yes, no → 2 values

• Full Combinations: 3 × 3 × 2 × 2 = 36 tests.
• Pairwise Minimum: 3 × 3 = 9 test cases!

3. Cause-Effect Graphing (CEG) in 7 Simple Steps

When business logic has interdependent rules (e.g. "If VIP AND balance > 1000 OR overdraft enabled, approve transfer"), Cause-Effect Graphing systematically prevents missing test cases.

📋 The 7-Step Process (Slide 18):

  1. Divide specification into workable features/rules.
  2. Identify Causes (distinct input conditions or equivalence classes).
  3. Identify Effects (output actions or system state changes).
  4. Draw Boolean graph linking causes to effects with logic gates: AND, OR, NOT, Identity.
  5. Add Constraints for impossible combinations (E, I, O, R).
  6. Convert graph into Decision Table (each column represents one test case).
  7. Execute test cases corresponding to columns.

The Core Constraint Symbols (Slide 20)

Symbol Name Rule Meaning
E Exclusive At most one cause can be true (0 or 1). Both cannot be true simultaneously.
I Inclusive At least one cause must be true (cannot both be false).
O One and Only One Exactly one cause must be true (e.g. Account Type is either Savings OR Checking).
R Requires If Cause A is true, then Cause B must also be true.
M Masks (Effects) If Effect 1 occurs, Effect 2 is suppressed/masked.
