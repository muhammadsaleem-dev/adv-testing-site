🏛️ Official Q DAY 8 CLOSING QUESTION (DEEP VS LIGHT)

Source: CH07_Block_D_Risk_Based_Testing.pdf

Which FinCon requirement would you test most deeply, and which requirement would you test only lightly?

Justify your answer using:

  • probability,
  • impact,
  • requirement criticality,
  • test cost,
  • required confidence.

Suggested Answer:

Criteria Test Deeply:
Transfer Limit Validation		 Test Lightly:
Dashboard Color Theme
Probability High (Complex business logic prone to off-by-one boundary errors). Low (Static CSS values rarely break logically).
Impact Critical (Direct financial loss). Low (Cosmetic annoyance, no functional blockage).
Req. Criticality Core requirement for legal/financial compliance. Non-essential aesthetic requirement.
Test Cost High ROI. Expensive to automate, but the cost of a defect is astronomically higher. Low ROI. Visual regression tools are expensive to maintain for low-value cosmetic checks.
Req. Confidence Stakeholders require absolute 100% confidence before release. Stakeholders can accept bugs here being fixed in a later patch.
