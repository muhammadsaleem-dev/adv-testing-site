🏛️ Official Q PAIRWISE TESTING (4 P)

Source: CH03_Block_B_Pairwise_CEG.pdf

A FinCon report export has three parameters:

Parameter Values format PDF / CSV / XML date_range last 7 days / last 30 days / custom include_cancelled yes / no
  • Full combination would require 18 test cases.

Perform the following tasks:

  • (a) Explain what pairwise testing guarantees that the full combination also guarantees — and what it does not guarantee.
  • (b) Construct a pairwise test suite for these three parameters. How many test cases does your suite contain? Verify that at least two specific pairs are covered.
👁️ Model Answer & Rubric Click to reveal Suggested Answer

Suggested Answer:

(a) Guarantees of Pairwise Testing (1 P):

  • What it guarantees: Pairwise testing guarantees that every possible combination of any two parameters (e.g., every format with every date_range) is covered by at least one test case.
  • What it does not guarantee: It does not guarantee coverage of 3-way or higher-order interactions (e.g., a specific bug that only occurs when PDF + custom + yes are used together might be missed).

(b) Pairwise Test Suite (3 P):

The largest product of two parameters is 3 × 3 = 9 (format × date_range), so a minimum of 9 test cases are required. A valid orthogonal array:

TC Format Date_Range Include_Cancelled 1 PDF 7 days yes 2 PDF 30 days no 3 PDF custom yes 4 CSV 7 days no 5 CSV 30 days yes 6 CSV custom no 7 XML 7 days yes 8 XML 30 days no 9 XML custom yes

Verification of two specific pairs (e.g., CSV + yes, XML + 30 days): CSV + yes is covered in TC 5. XML + 30 days is covered in TC 8.

🏛️ Official Q CAUSE-EFFECT GRAPHING (4 P)

Source: CH03_Block_B_Pairwise_CEG.pdf

FinCon applies the following rule for overdraft protection:

  • If the account has overdraft protection enabled and the overdraft limit is not exceeded, a payment below the account balance is approved.
  • If the account has no overdraft protection and the balance is insufficient, the payment is rejected with INSUFFICIENT_FUNDS.
  • If the overdraft limit would be exceeded, reject with OVERDRAFT_LIMIT_EXCEEDED.

Perform the following tasks:

  • (a) Identify all causes and effects.
  • (b) Build a decision table covering all valid combinations.
  • (c) State how many test cases result and explain whether any combinations are impossible.
👁️ Model Answer & Rubric Click to reveal Suggested Answer

Suggested Answer:

(a) Causes and Effects (1 P):

  • Causes: C1: Overdraft protection enabled, C2: Payment below account balance (sufficient funds), C3: Overdraft limit exceeded.
  • Effects: E1: Approved, E2: Rejected with INSUFFICIENT_FUNDS, E3: Rejected with OVERDRAFT_LIMIT_EXCEEDED.

(b) Decision Table (2 P):

Rule C1(OD) C2(BalOK) C3(LimitExc) | Expected Effect R1 True True N/A | Approved (E1) R2 True False False | Approved (E1) R3 True False True | OVERDRAFT_LIMIT_EXCEEDED (E3) R4 False True N/A | Approved (E1) R5 False False N/A | INSUFFICIENT_FUNDS (E2)

(c) Test Cases and Impossible Combinations (1 P):

While 3 boolean causes yield 2^3 = 8 theoretical combinations, several are impossible or redundant. If C2 is True (sufficient funds), the overdraft limit (C3) cannot mathematically be exceeded, rendering those combinations impossible/N/A. Likewise, if OD is False (C1), the overdraft limit (C3) does not exist. Collapsing these yields 5 valid test cases.

🏛️ Official Q AI OUTPUT REVIEW (4 P)

Source: CH03_Block_B_Pairwise_CEG.pdf

You give an LLM the FinCon debit handling specification from the lecture and receive these test cases:

>>> debit(account_active=True, balance=1000, amount=500) 'approved' >>> debit(account_active=False, balance=1000, amount=500) 'INSUFFICIENT_FUNDS' >>> debit(account_active=True, balance=100, amount=500) 'INSUFFICIENT_FUNDS' >>> debit(account_active=True, balance=0, amount=1) 'approved'

Perform the following tasks:

  • (a) Identify two factual errors in the AI output.
  • (b) Identify one important combination missing from this test suite.
  • (c) Rewrite the test suite with corrections and additions.
👁️ Model Answer & Rubric Click to reveal Suggested Answer

Suggested Answer:

(a) Two factual errors (2 P):

  • Error 1: In the second test case, an inactive account (account_active=False) with plenty of funds (1000) returns 'INSUFFICIENT_FUNDS'. This is a hallucinated error code; it should return a state-specific error like 'ACCOUNT_INACTIVE'.
  • Error 2: In the fourth test case, an account with a balance of 0 trying to debit 1 returns 'approved'. This is completely false and would result in an unauthorized negative balance.

(b) Missing combination (1 P):

The suite misses the combination of multiple failure conditions (e.g., account_active=False AND insufficient balance) to verify error priority, as well as missing boundary values (debiting the exact balance amount, e.g., balance=500, amount=500).

(c) Rewritten test suite (1 P):

>>> debit(account_active=True, balance=1000, amount=500) 'approved' >>> debit(account_active=False, balance=1000, amount=500) 'ACCOUNT_INACTIVE' >>> debit(account_active=True, balance=100, amount=500) 'INSUFFICIENT_FUNDS' >>> debit(account_active=True, balance=0, amount=1) 'INSUFFICIENT_FUNDS' >>> debit(account_active=True, balance=500, amount=500) 'approved'
