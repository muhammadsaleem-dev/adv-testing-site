Advanced Testing Methods · Exam Guide

1. Fundamentals & Terms

Key concepts and techniques

Core idea: Testing reduces uncertainty by comparing actual behaviour with expected behaviour.

What makes a test case complete?

  • Preconditions: What must already be true before execution.
  • Input and action: Exact reproducible values and steps.
  • Expected result (oracle): What should happen if the system is correct.
  • Postconditions: The state that should exist after the test, when relevant.

Triangle lesson

Even a tiny triangle classifier needs valid scalene, equilateral and isosceles cases; all isosceles permutations; zero and negative values; degenerate triangles; non-triangles; wrong input types; wrong number of values; and expected results. Small programs can still have a large test space.

Non-negotiable AI rule: Expected results must come from the specification, not from the LLM and not from the implementation. Otherwise the test may simply confirm the same wrong assumption.

Worked exam questions

✏️ Q1 (3 marks) (Source) A developer accidentally applies a rounding function twice. The screen shows a wrong balance. Name the three stages.

The copy-paste action is an error. The duplicate function call in code is the defect/bug. The wrong displayed balance is the failure.

✏️ Q2 (3 marks) Why is “the testers fixed the bug” inaccurate?

Testers design and execute tests, observe failures and report defects. Debugging - locating and removing the cause - is normally development responsibility. A corrected statement is: testers found the failure and reported the defect; developers debugged and fixed it.

✏️ Q3 (4 marks) Name two risks of using 20 LLM-generated login tests directly.

Possible answers: hallucinated expected results; happy-path bias; missing security and boundary cases; circular tests that mirror code; duplicate coverage; false confidence. For full marks, give a concrete example and explain the consequence.
