5. AI-Generated Code & Static Analysis

Key concepts and techniques

AI-generated code often looks correct. Review it against the specification before trusting coverage or generated tests.

Typical AI-code defect patterns

PatternExampleWhy coverage may miss it
Dead path from hallucinated logicExtra branch that cannot be reachedCoverage shows a gap but cannot explain the intended rule.
Plausible but invented boundaryAge restricted to <=120 although spec has no maximumTests generated from the same code can validate the invented rule.
Copy-paste semantic errorRefund calls debit instead of credit100% statement/branch coverage can still execute the wrong method.
Duplicate branch logicDifferent labels return identical resultAll branches can run but the business distinction is absent.
Wrong test oracleExpected result copied from implementationThe test confirms the defect instead of revealing it.

AI-code review checklist

  1. Read the specification and list valid/invalid inputs and outputs.
  2. List every branch; mark branches not required by the specification.
  3. Check reachability and dead code.
  4. Compare all boundaries with the specification.
  5. Look for duplicate or near-duplicate branch logic.
  6. Derive test oracles independently.
  7. Only then measure coverage and investigate gaps.

Static analysis versus inspection

TechniqueHow it worksStrengthLimitation
Static analysisTool reads code without executing itFast; catches type/data/control-flow issuesFalse positives; weak business understanding
Code inspectionHuman reviews systematicallyFinds logic, design and specification mismatchesNeeds skill and discipline
Dynamic testingExecutes softwareObserves real behaviour and failuresOnly covers executed cases

Common data reference defects

# Use before assignment
for item in items:
    if item.valid:
        result = item.value
return result  # fails if no valid item

# Mutable default
def append_log(msg, log=[]):  # same list reused across calls
    log.append(msg)

# Variable shadowing
amount = 1000
def calculate():
    amount = amount * 0.9  # UnboundLocalError

Worked exam questions

✏️ Duplicate tier branch (4 marks) (Source) A bronze branch repeats the exact silver condition, but bronze is not in the specification.

Defects: the bronze condition is unreachable because the earlier identical silver branch always matches; bronze is an unsupported tier. A strict 100% branch target cannot be reached while that dead branch exists. Coverage can expose an unexecuted branch but not decide the correct business tiers. No ordinary input test can execute the unreachable line; static inspection plus a specification-based test for representative silver/basic values is required.

✏️ Static defects (3 marks) batch_transfer has logger=[] and assigns summary but never uses it.

logger=[] is a mutable default argument and causes state to persist across calls; Pylint/Ruff and review can detect it. summary is an unused variable; Pylint/Ruff can detect it. Mypy is not the main tool unless useful type annotations exist.

✏️ Why inspection still matters (3 marks) Give defects branch coverage can miss.

Examples: invented age maximum; debit instead of credit in refund; duplicate branches with identical results; unsupported business tier. Static tools can more reliably flag use-before-assignment, mutable defaults, unreachable code after return/raise, and type mismatches.
