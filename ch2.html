2. EC & BVA

Key concepts and techniques

Black-box tests are derived from the specification, not from the code.

Equivalence Class Method (EC)

  1. Identify each input parameter.
  2. Define its type, range, format and special rules.
  3. Split the domain into valid and invalid classes.
  4. Split again wherever different behaviour is expected.
  5. Choose one representative per class.
  6. Combine representatives into test cases.

Boundary Value Analysis (BVA)

  • Bugs often cluster where rules change.
  • For each boundary, test just below, exactly at, and just above.
  • For amount [1, 100000], use 0, 1, 2, 99999, 100000, 100001.
  • Expected results are essential; a list of values alone is not a complete answer.

Multiple inputs and combinatorial explosion

  • If parameter A has 6 interesting values and B has 9, full combination already creates 54 vectors.
  • Test each valid class of one parameter with valid complements.
  • Test each invalid class with all other parameters valid so the failure cause is isolated.
  • Add high-risk interactions identified from domain knowledge.

Worked exam questions

✏️ PIN equivalence classes (3 marks) (Source) The login PIN is a 4-digit numeric string. Define complete classes.

Valid: exactly four digits, e.g. “1234”, accepted as format-valid. Invalid: fewer than four digits (“123”); more than four (“12345”); contains a non-digit (“12A4”); whitespace (“12 4”); empty/missing; wrong type such as integer 1234 if the interface requires a string. Each invalid class is rejected.

✏️ Interest boundary (4 marks) Bonus interest is 1.5% only on balance above EUR 10000.

Use 9999.99 -> 0; 10000.00 -> 0; 10000.01 -> 0.00015 if values are exact euros. With integer euros: 9999 -> 0; 10000 -> 0; 10001 -> 0.015. Testing only 5000 and 15000 misses the exact threshold and off-by-one errors.

✏️ Multi-input test gap (3 marks) Tests are (500, True), (0, False), (200000, False) for amount and target_exists.

The invalid amount is always combined with an invalid target, so the reason for rejection is masked. The target-not-found class is never tested with a valid amount. Add (500, False) -> rejected/unknown target. Also add invalid amount with target=True to isolate amount validation.
