2. EC & BVA

Key concepts and techniques

🎯 Chapter 2 Core Mission: Defeating Combinatorial Explosion with Equivalence Partitioning

Exhaustive testing is mathematically impossible. A 32-bit integer has over 4.29 billion possible inputs. Equivalence Partitioning (EC) and Boundary Value Analysis (BVA) allow us to test billions of possibilities with just a handful of carefully selected representatives.

1. Equivalence Partitioning (EP / EC Method)

An Equivalence Class is a subset of input or output data where the system is specified to treat all values within that class identically. If one value in an equivalence class uncovers a defect, all other values in that same class will likely uncover the exact same defect.

✅ Valid Equivalence Classes

Values that should be accepted and processed by the system according to valid business rules.
Rule: You may combine multiple valid equivalence classes into a single test case to reduce test count.

❌ Invalid Equivalence Classes

Values that must be rejected, triggering error handling, validation messages, or exceptions.
Cardinal Rule (Exam Trap): Never combine two invalid equivalence classes in one test case! Testing two invalid inputs together causes error masking.

The Standard Exam Table Format:

Equivalence Class Representative Value Expected Result Class Type
EC1: Valid PIN (4 numeric digits) "1234" Accepted / Login proceeds Valid
EC2: Too short (< 4 digits) "123" Rejected / ValueError Invalid
EC3: Too long (> 4 digits) "12345" Rejected / ValueError Invalid
EC4: Non-numeric characters "12a4" Rejected / ValueError Invalid

2. Boundary Value Analysis (BVA)

Empirical defect studies show that the vast majority of software defects occur at the boundaries of equivalence partitions rather than in their interior (e.g. developers writing > instead of >=, or loop off-by-one errors).

2-Value vs. 3-Value Boundary Testing

2-Value Boundary Testing (ISTQB Standard):

Tests the exact boundary value (on the boundary) and its nearest neighbor in the adjacent partition (just over the boundary).
Example for valid range [5, 40]:
Lower: 4 (invalid), 5 (valid)
Upper: 40 (valid), 41 (invalid)

3-Value Boundary Testing (Strong BVA):

Tests the boundary value, the value immediately below it, and the value immediately above it.
Example for valid range [5, 40]:
Lower: 4 (invalid), 5 (valid), 6 (valid)
Upper: 39 (valid), 40 (valid), 41 (invalid)

Boundary Point Tested Value Expected Outcome Technical Justification
Lower Bound - 1 4 Rejected (ValueError) Just below lower boundary (tests underflow guard)
Lower Bound (Min) 5 Accepted Exact lower inclusive boundary
Lower Bound + 1 6 Accepted Just inside lower boundary (strong BVA)
Upper Bound - 1 39 Accepted Just inside upper boundary (strong BVA)
Upper Bound (Max) 40 Accepted Exact upper inclusive boundary
Upper Bound + 1 41 Rejected (ValueError) Just above upper boundary (tests overflow guard)

3. Multi-Dimensional Test Data & Partition Independence

Real systems take multiple independent inputs. For example, a FinCon transfer function requires both an amount ($1$ to $100,000$ cents) and a target_account (valid IBAN string).

Core Multi-Dimensional Rule:

When testing an invalid partition for one parameter (e.g., negative amount), all other parameters must be valid representatives. If you pass an invalid amount AND an invalid target account simultaneously, you cannot know which guard triggered the rejection or if one of the checks failed silently!
