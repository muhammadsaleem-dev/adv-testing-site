Definitions you must not confuse

PairDifference
Error vs defect vs failureHuman mistake vs flaw in artifact vs observable wrong behaviour
Testing vs debuggingDetect/report vs locate/remove cause
Severity vs priorityImpact vs fixing order
Authentication vs authorizationIdentity vs permission
BDD vs Gherkin vs behaveApproach vs language vs execution framework
Load vs stressExpected workload vs push until degradation
Pass vs product qualityA passing test only confirms its covered example

Common exam traps

  • Listing values without expected results.
  • Combining two invalid parameters and then claiming both validations were tested.
  • Calling a human mistake a bug instead of an error.
  • Calling an observable failure a defect.
  • Claiming pairwise coverage without checking pairs.
  • Using condition coverage as proof of MC/DC.
  • Believing 100% coverage proves correctness.
  • Writing vague Gherkin: "data", "works", "correct".
  • Treating AI output as an oracle.
