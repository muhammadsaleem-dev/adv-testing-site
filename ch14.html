14. Mock Exam A Answers

Key concepts and techniques

Mock Exam A - Model Answers

✏️ A1 - EC and BVA (6 marks) A transfer amount must be an integer from 1 to 50000 inclusive. Define equivalence classes and list strong boundary values with expected results.

Classes: below 1; valid 1..50000 integer; above 50000; non-integer; missing/wrong type. Strong boundaries: 0 reject, 1 accept, 2 accept, 49999 accept, 50000 accept, 50001 reject. Add 10.5 reject for non-integer.

✏️ A2 - Isolation (4 marks) A test suite contains (amount=0, session_valid=False) and (amount=60000, session_valid=False). Explain the structural problem and add two better tests.

Both tests combine invalid amount with invalid session, so the rejection cause is masked and the invalid-session rule is not tested with a valid amount. Add (amount=500, session_valid=False) -> reject session; add (amount=0, session_valid=True) -> reject amount. A separate upper-invalid test can use (60000, True).

✏️ A3 - Pairwise (5 marks) Parameters: browser Chrome/Firefox; role customer/admin; language EN/DE/FR. State the pairwise minimum and identify a suitable table.

Largest pair is browser x language = 2 x 3 = 6, so minimum is at least 6. One table: Chrome/customer/EN; Chrome/admin/DE; Chrome/customer/FR; Firefox/admin/EN; Firefox/customer/DE; Firefox/admin/FR. Verify each role pairs with both browsers and all three languages.

✏️ A4 - Login decision table (5 marks) Login succeeds when user exists, password is correct, and account is not locked. If locked, return LOCKED regardless of credentials. Build a compact decision table.

Use four meaningful rules: exists=yes, password=correct, locked=no -> success; exists=no, locked=no -> invalid credentials; exists=yes, password=wrong, locked=no -> invalid credentials; locked=yes with any credentials -> LOCKED.

✏️ A5 - MC/DC (5 marks) Decision: if session_valid and (amount_valid or manager_override): approve. Construct a minimum MC/DC suite.

Let S=session, A=amount, M=override. Use T,T,F -> approve; F,T,F -> reject (S independence); T,F,F -> reject (A independence compared with first); T,F,T -> approve (M independence compared with third).

✏️ A6 - Static analysis (4 marks) Find two issues: def add_event(event, events=[]): events.append(event); note="stored"; return len(events). Name likely tools.

events=[] is a mutable default, so state persists between calls; Pylint/Ruff and review can detect it. note is assigned but unused; Pylint/Ruff detects it. The function should use events=None and create a new list when needed.

✏️ A7 - Gherkin (4 marks) Repair: Scenario: Payment works / Given user has data / When user submits / Then it is correct. Rule: amount above 50000 must be rejected.

Scenario: Reject payment above the maximum amount / Given a logged-in user has sufficient balance / When the user submits a payment of 50001 cents / Then the payment is rejected / And no money is debited. This gives concrete data, one action and observable outcomes.

✏️ A8 - Risk and test level (4 marks) You can run only two tests: UI label spelling, transfer after expired session, report colour, transfer above limit. Choose two and justify.

Choose transfer after expired session and transfer above limit. Both have high financial/security impact. Test the session case at API/integration and possibly one system workflow; test the limit with BVA at unit/API. UI spelling and report colour are lower impact and can be deferred.

✏️ A9 - Performance (3 marks) Classify: 200 expected users for one hour; 50 to 1000 users in one minute; account with 100000 records.

200 expected users for one hour = load test. 50 to 1000 in one minute = spike test. 100000 records = volume test.

✏️ A10 - Security (4 marks) A user logs in correctly but reads another user’s balance. Classify the security area and propose evidence at two test levels.

This is an authorization defect: the user is authenticated but lacks permission to read another account. At API/component level, request another user’s account and expect forbidden/no data. At system level, verify the UI cannot navigate to or display that balance and an audit event is recorded if required.

Original Slide-Deck Mock Exam - Questions and Answers

🏛️ Question 1 - Voucher boundaries Discount must be an integer from 5 to 40 inclusive. List boundary values, expected results and one extra invalid class.

4 (reject), 5 (accept), 6 (accept), 39 (accept), 40 (accept), 41 (reject). Extra invalid: 10.5 (reject).

🏛️ Question 2 - Pairwise gap Format PDF/CSV, Summary Yes/No, Language EN/DE/FR. Proposed suite has four rows.

Largest pair = Format x Language = 2 x 3 = 6; fewer than 6 cannot be sufficient. Add PDF / No / FR to cover PDF-FR and No-FR.

🏛️ Question 3 - Gherkin critique Critique: Given user is logged in, when he transfers, then everything is correct.

Weak title, no concrete amount, combined/vague action, and “everything is correct” is not an oracle.

🏛️ Question 4 - Static analysis and coverage Critique: events=[], message="done" unused, and test only covers approval path.

log=[] is a mutable default. message="done" is unused. The provided test covers only approval. Add a rejection path.

🏛️ Question 5 - Security risk decision Chatbot reveals another user balance and starts a transfer.

Highest priorities: chatbot reveals another customer’s balance (confidentiality) and chatbot starts a transfer from chat (integrity). Prompt injection is also high priority.
