🏛️ Official Q & A Q2 — PAIRWISE GAP

Source: CH10_Block_F_Security_Testing_Mock_Exam_Prep.pdf

A report export function has these parameters:

Parameter Values Format PDF / CSV Include summary Yes / No Language EN / DE / FR

Proposed test suite:

TC Format Summary Language 1 PDF Yes EN 2 PDF No DE 3 CSV Yes FR 4 CSV No EN

Perform the following tasks:

  • (a) What is the pairwise minimum?
  • (b) Identify one missing 2-way pair.
  • (c) Add one test case that covers that missing pair.
👁️ Model Answer & Rubric Click to reveal Suggested Answer

Suggested Answer:

(a) Pairwise minimum:

Largest pair = Format × Language = 2 × 3 = 6. Therefore, fewer than 6 test cases cannot be sufficient.

(b) Identify one missing 2-way pair:

  • Format × Language: PDF × FR or CSV × DE
  • Summary × Language: No × FR or Yes × DE

(c) Add one test case that covers that missing pair:

One valid additional test case is: PDF, No, FR (Covers PDF × FR and No × FR).

🏛️ Official Q & A Q3 — GHERKIN CRITIQUE

Source: CH10_Block_F_Security_Testing_Mock_Exam_Prep.pdf

A student writes this scenario:

Scenario: Transfer works Given the user is on the transfer page When the user enters data and confirms the transfer Then everything is correct

Rule: Transfers above 100000 cents must be rejected.

Perform the following tasks:

  • (a) Identify two weaknesses in the scenario.
  • (b) Rewrite it as one concise Gherkin scenario with observable expected results.
👁️ Model Answer & Rubric Click to reveal Suggested Answer

Suggested Answer:

(a) Two weaknesses:

  • Vague title: Does not name the business rule being tested.
  • Vague input / Combined action: No concrete amount is stated, and "enters data and confirms" hides the relevant specific trigger event.
  • Vague expected result: "everything is correct" cannot pass/fail objectively.

(b) Improved Gherkin scenario:

Scenario: Reject transfer above the maximum amount Given a logged-in FinCon user has a balance of 200000 cents And the target account exists When the user submits a transfer of 100001 cents Then the transfer is rejected And no money is debited from the source account

🏛️ Official Q & A Q4 — STATIC ANALYSIS AND COVERAGE

Source: CH10_Block_F_Security_Testing_Mock_Exam_Prep.pdf

Given code:

def approve_transfer(amount, target_exists, session_valid, log=[]): approved = False if amount >= 1 and amount <= 100000: if target_exists: if session_valid: approved = True log.append("approved") message = "done" return approved

One test uses: amount = 500, target_exists = True, session_valid = True

Perform the following tasks:

  • (a) Identify two static defects or quality problems.
  • (b) State which tool type would likely detect each.
  • (c) Give one important rejection-path test not covered by the given test.
👁️ Model Answer & Rubric Click to reveal Suggested Answer

Suggested Answer:

(a & b) Static defects and likely detection tools:

  • Defect: Mutable default argument log=[]
    Likely detection: Linter such as Pylint; or code review.
  • Defect: Unused variable message
    Likely detection: Linter such as Pylint or Ruff.

(c) Coverage issue / Rejection-path test:

The given test covers only the approval path. It does not cover rejection behavior. One valid additional test:

amount = 0, target_exists = True, session_valid = True → Expected: False

🏛️ Official Q & A Q5 — SECURITY RISK DECISION

Source: CH10_Block_F_Security_Testing_Mock_Exam_Prep.pdf

FinCon introduces a support chatbot that can answer account questions, but it must not reveal personal account data or execute transfers.

Possible risks:

  1. Prompt injection makes the bot ignore its rules.
  2. The bot reveals another customer's balance.
  3. The bot gives a vague answer to a help question.
  4. The bot starts a transfer from a chat instruction.

Perform the following tasks:

  • (a) Select the two highest-priority security risks and justify your choice using impact and test response.
👁️ Model Answer & Rubric Click to reveal Suggested Answer

Suggested Answer:

(a) Strongest selection and justification:

Selected Risk Priority Reason (Impact) Test Response
Bot reveals another customer's balance Confidentiality breach; personal/financial data exposure Adversarial authorization tests; data isolation checks
Bot starts a transfer from chat instruction Integrity and financial safety risk Negative workflow tests; permission boundary tests

(Note: Prompt injection is also acceptable if justified correctly as a high-priority attack mechanism leading to data disclosure or unauthorized action. Vague help answers are lower priority usability issues, not high security risks.)
