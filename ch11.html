Key concepts and techniques

🎯 Chapter 11 Core Mission: The FinCon BudgetControl System Architecture & HLRS

BudgetControl (FinCon) is the course-long banking application used across all exam scenarios. Understand its multi-tier component architecture, High-Level Requirements (HLRS), and end-to-end user stories.

1. Multi-Tier System Architecture

  • Frontend Presentation Layer: Web UI (HTML5/JS) + Mobile Banking Interface.
  • API & Gateway Layer: Session authentication, rate-limiting, and request validation.
  • Core Business Engine (FinCon Core):
    • Transfer Engine: Validates amounts (1–100k cents), balances, and overdraft limits.
    • Beneficiary Manager: Manages verified recipient IBANs and step-up 2FA confirmation.
    • Voucher & Interest Service: Handles discount percentages (5–40%) and savings tier calculations.
  • Data & Persistence Layer: Relational Database (Accounts, Ledgers) + Immutable Audit Log Store.

2. High-Level Requirements (HLRS) Traceability

Req ID Requirement Description Associated Test Level & Response
HLRS-R1 Login PIN must be exactly 4 numeric digits. Unit & Equivalence class testing (valid & invalid PINs).
HLRS-R2 Transfer amount must be an integer between 1 and 100,000 Euro cents. Boundary Value Analysis (0, 1, 100k, 100001) + API negative tests.
HLRS-R3 Session token must be valid and non-expired to execute financial actions. Integration tests with expired tokens & unauthorized requests.
HLRS-R4 Every transfer attempt (success or fail) must be recorded in the audit log. Database integration assert queries verifying audit table row generation.
