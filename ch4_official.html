4. White-Box Coverage & MC/DC

Official Questions

🏛️ Official Q COVERAGE SUBSUMPTION (3 P)

Source: AdvTest_05_Cover_Mock_full.pdf

A colleague analyzes the following function:

def transfer(amount: float, target_exists: bool, daily_limit: float) -> str: if amount <= 0: return "invalid" if not target_exists: return "unknown_target" if amount > daily_limit: return "limit_exceeded" return "approved"

Perform the following tasks:

  • (a) How many test cases are needed for 100% statement coverage?
  • (b) How many test cases are needed for 100% branch coverage?
  • (c) A colleague achieves 100% statement coverage but misses the "limit_exceeded" path. Explain why this is possible and what it reveals about statement coverage as a sole criterion.

Suggested Answer:

(a) Test cases for 100% statement coverage (1 P):

4 test cases. To execute every statement in this function, we must trigger every return statement. Because they are mutually exclusive branches, this requires exactly 4 test cases.

(b) Test cases for 100% branch coverage (1 P):

4 test cases. Because the function consists purely of guard clauses that exit early, traversing all True branches and the final False fall-through path automatically covers all branches.

(c) Missing the path despite 100% statement coverage (1 P):

(Trick question / logical nuance): In this specific implementation, it is mathematically impossible to achieve 100% statement coverage and miss the "limit_exceeded" path, because return "limit_exceeded" is itself a statement. If the colleague missed it, they do not actually have 100% statement coverage.

However, if the code were written differently (e.g., using a single status variable updated by multiple if statements without early returns), one could hit all statements while skipping a specific logical branch. This reveals that statement coverage is a weak metric because it only guarantees code was executed, not that all logical control-flow permutations were tested.

🏛️ Official Q MC/DC (4 P)

Source: AdvTest_05_Cover_Mock_full.pdf

FinCon applies this rule:

if is_premium and (balance > 10000 or overdraft_enabled): apply_bonus_rate()
  • There are three conditions: is_premium (P), balance > 10000 (B), overdraft_enabled (O).

Perform the following tasks:

  • (a) How many test cases does MC/DC require at minimum?
  • (b) Construct a minimal MC/DC test suite. For each test case, show which condition's independence it demonstrates.
  • (c) Explain why condition coverage alone would not be sufficient here.

Suggested Answer:

(a) Minimum MC/DC test cases (1 P):

For N independent conditions, Modified Condition/Decision Coverage (MC/DC) requires N + 1 test cases. Here N=3, so 4 test cases are required at minimum.

(b) Minimal MC/DC suite (2 P):

TC P B O | Outcome 1 True True False | True 2 False True False | False 3 True False False | False 4 True False True | True
  • Independence of P: Pair TC 1 and TC 2 (P changes, B and O held constant, outcome changes).
  • Independence of B: Pair TC 1 and TC 3 (B changes, P and O held constant, outcome changes).
  • Independence of O: Pair TC 3 and TC 4 (O changes, P and B held constant, outcome changes).

(c) Insufficiency of Condition Coverage (1 P):

Condition coverage merely requires that each individual condition (P, B, O) evaluates to both True and False at least once across the suite. It does not guarantee that the condition actually affects the final decision, nor does it guarantee that the overall decision itself takes on both True and False outcomes.

🏛️ Official Q MOCKS (4 P)

Source: AdvTest_05_Cover_Mock_full.pdf

You are given the following function:

def send_transfer(amount: int, recipient_id: str, db, notifier) -> str: recipient = db.find_account(recipient_id) if recipient is None: return "recipient_not_found" db.debit_sender(amount) db.credit_recipient(recipient, amount) notifier.send_email(recipient.email, amount) return "transfer_complete"

Perform the following tasks:

  • (a) Write a unittest test case using MagicMock that verifies the happy path: both debit_sender and credit_recipient are called, and notifier.send_email is called with the correct recipient email.
  • (b) Write a test case that verifies that when db.find_account returns None, neither debit_sender nor credit_recipient is called.

Suggested Answer:

(a) Happy Path Mock Test (2 P):

from unittest.mock import MagicMock def test_send_transfer_happy_path(): # 1. Setup mocks db = MagicMock() notifier = MagicMock() mock_recipient = MagicMock() mock_recipient.email = "test@example.com" db.find_account.return_value = mock_recipient # 2. Execute result = send_transfer(500, "rec_123", db, notifier) # 3. Assert outputs and interactions assert result == "transfer_complete" db.debit_sender.assert_called_once_with(500) db.credit_recipient.assert_called_once_with(mock_recipient, 500) notifier.send_email.assert_called_once_with("test@example.com", 500)

(b) Negative Path Mock Test (2 P):

def test_send_transfer_recipient_not_found(): # 1. Setup mocks db = MagicMock() notifier = MagicMock() db.find_account.return_value = None # 2. Execute result = send_transfer(500, "invalid_id", db, notifier) # 3. Assert outputs and non-interactions assert result == "recipient_not_found" db.debit_sender.assert_not_called() db.credit_recipient.assert_not_called() notifier.send_email.assert_not_called()
