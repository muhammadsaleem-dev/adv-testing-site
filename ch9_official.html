9. Web Automation & Perf

Official Questions

These are the Official Practice Questions provided by the Professor in the slide deck for Chapter 9.

🏛️ Official Q WEAK AUTOMATION PROPOSAL (4 P)

Source: CH09_Block_E_Web_Performance.pdf

A junior tester submits the following web UI automation script proposal:

1. Open transfer page. 2. Fill any amount. 3. Click the third button. 4. Wait 5 seconds. 5. Check that the page changed.

Perform the following tasks:

  • (a) Identify at least three weaknesses in the script.
  • (b) Rewrite one step to make it robust.
  • (c) Name one expected result that would act as a real oracle.
👁️ Model Answer & Rubric Click to reveal Suggested Answer

Suggested Answer:

(a) Weaknesses:

Weakness Reason / Improvement
"any amount" Not reproducible. Use controlled test data (e.g., 500 cents).
"third button" Fragile locator. UI changes will break it. Use explicit label, role, or test-id.
"Wait 5 seconds" Flaky and slow. Should wait dynamically for a specific confirmation state (element visibility).

(b & c) Robust Rewrite & Oracle:

  • Rewrite: Instead of "Check that the page changed", explicitly verify the resulting state.
  • Oracle: Verify that the success message appears, the target account shows the credited amount, and a transfer ID is generated.
