6. Test Process & MTS

Key concepts and techniques

🎯 Chapter 6 Core Mission: Steering Testing as a Professional Process (GTP & MTS)

Testing without a structured process is ad-hoc chaos. Master the 6-Phase Generic Test Process (GTP), the architecture of a Master Test Strategy (MTS), objective Quality Gates (Entry & Exit Criteria), and Decision-Oriented Metrics.

1. The 6 Phases of the Generic Test Process (GTP)

ISTQB 4.0 structures professional software testing into 6 iterative phases:

Phase Core Strategic Question Key Deliverable / Artifact
1. Planning What is the scope, budget, risks, test levels, and schedule? Master Test Strategy (MTS) / Test Plan
2. Analysis What must be tested? (Identify testable conditions from requirements). Test Conditions, Traceability Matrix
3. Design How should conditions be tested? (Specify test data & oracles). High-level Test Cases, BVA & Decision Tables
4. Implementation Are tests executable and automated? (Write scripts & seed DB). Pytest scripts, Gherkin feature files, CI pipelines
5. Execution & Reporting What actually happened? Does evidence justify release? Test Logs, Defect Reports, Test Summary Report
6. Completion / Closure What reusable testware and lessons learned should be archived? Archived Testware, Process Improvement Retrospective

2. Quality Gates: Entry & Exit Criteria

A central responsibility in test strategy is defining objective quality gates. Never use vague language like "software is ready" or "all tests completed".

📋 Standard Entry Criteria (Start Testing)

  • Automated CI build succeeds with 100% unit test pass rate.
  • Unit branch coverage exceeds ≥ 90%.
  • Test environment is deployed with mock banking APIs and test accounts provisioned.
  • All testable requirements are reviewed and approved.

🚩 Standard Exit Criteria (Release to Production)

  • 100% of P1 & P2 (Critical/High) test cases executed with 100% pass rate.
  • Zero open Critical or High severity defects.
  • Residual risk assessment reviewed and approved by Product Owner.
  • User documentation and release notes verified.

3. Test Metrics: Decision-Oriented vs. Vanity Metrics

Golden Rule: Start with the Stakeholder Decision Question!

Decision-Oriented Metric: "Open defects by risk area" or "Pass rate of critical financial workflows" directly tells stakeholders if customer money is safe.
Misleading / Vanity Metric: "Total test case count (e.g. 5,000 tests executed)" only measures activity or volume — 5,000 green button-color tests mean nothing if the single money transfer test is failing!
