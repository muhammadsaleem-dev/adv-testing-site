6. Generic Test Process & MTS

Key concepts and techniques

Testing is a controlled information process: uncertainty -> evidence -> decision.

Generic Test Process (GTP)

PhaseMain questionTypical output
1. PlanningWhat, why, how much, who, when?scope, risks, levels, entry/exit criteria
2. Analysis and designWhat must be checked and which cases cover it?test conditions, cases, data, techniques
3. ImplementationAre tests executable and reproducible?scripts, automation, environment, prepared data
4. ExecutionWhat actually happened?pass/fail/blocked/inconclusive results
5. Evaluation and reportingIs evidence sufficient for the decision?risk status, open defects, recommendation
6. Closure and improvementWhat should be retained or improved?archived testware, lessons, regression updates
Iterative, not strictly linear: A failure during execution can send the team back to requirement clarification, test redesign, environment repair or risk reassessment.

Execution result meanings

  • Pass: Observed result matches expected result.
  • Fail: Observed result differs from expected result.
  • Blocked: Dependency/environment prevents execution.
  • Inconclusive: Result cannot be interpreted reliably.

Important: A failed test does not automatically mean a product defect. It can be a test defect, bad test data, environment problem or ambiguous requirement.

Master Test Specification (MTS)

SectionWhat it explains
PurposeWhy the strategy document exists
Subject under testFunctions and interfaces
Scope/non-scopeIncluded and deliberately excluded areas
Test basisRequirements, stories, rules, models
Risk analysisBusiness and technical risks
Test approachLevels, techniques, automation/manual split
Entry/exit criteriaStart and stop conditions
Reporting/metricsEvidence, defects, status and decisions

MTS is not a test-case list: It explains the logic behind the test effort: what is tested, why, how deeply, when enough evidence exists, and how results support decisions.
